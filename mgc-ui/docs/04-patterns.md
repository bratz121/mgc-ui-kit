**Боковое меню (`PlatformSidebar`)**

| Зона | Содержимое | Размеры |
|---|---|---|
| Шапка | Знак «ПК» 32px + «Производственный контур» (text-lg) + кнопка «Свернуть меню» | высота 64px, граница снизу |
| Площадка | Название площадки капсом, 12px, 700, трекинг 0.08em, `muted-foreground` | |
| Модули | Плитка 32px + название (16px). Чужие модули — внешние ссылки в новой вкладке | мин. высота строки 46px |
| Текущий модуль | Подложка `sidebar-accent`, стрелка ⌃/⌄ сворачивает разделы | |
| Разделы | Отступ слева 50px, 15px, `muted-foreground`; активный — `foreground` + красная полоса 3px слева | |
| Пользователь | Аватар 40px (инициалы на `brand-soft`), логин, таймер сессии, кнопка выхода (`outline`) | граница сверху |

Модуль с пустым `url` скрывается (кроме текущего) — как `buildSidebarApps` в `config/platforms.js`.
Меню сворачивается полностью (`collapsible="offcanvas"`), в шапке появляется кнопка его раскрытия.
Горячая клавиша — `Ctrl+B`. **Постоянно меню показано с 1024px**; уже (планшет, телефон, узкое окно) — выезжающая
панель, иначе 360px меню съедают контент. Группы разделов текущего модуля сворачиваются, группа активной страницы раскрыта.

```tsx
<SidebarProvider style={{ "--sidebar-width": "22.5rem" } as React.CSSProperties}>

    <PlatformHeader title="Заявки" onBack={…} actions={<ThemeToggle />} />

  </SidebarInset>

```

**Шапка (`PlatformHeader`)** — 64px, липкая. Слева: кнопка меню (если свёрнуто),
«← На главную» на внутренних страницах, разделитель, заголовок. Справа: версия, тема, помощь.

## Дашборд

Порядок блоков сверху вниз:

1. Заголовок страницы + контекст (дата, смена, время обновления) + переключатель периода (`ToggleGroup`).
2. Критичные сообщения (`Alert variant="critical"`) — только если есть.
3. Ряд KPI: 4 `StatCard` (`grid sm:grid-cols-2 xl:grid-cols-4`).
4. Главный график (2/3 ширины) + список участков/рейтинг (1/3).
5. Вторичные графики и последние записи (таблица в карточке).

## Реестр (список сущностей)

1. Заголовок + количество + основное действие справа («Новая заявка»).
2. Сводка по статусам: `StatCard` с `tone` (цвет полосы = категория).
3. Карточка-таблица: тулбар (поиск 288px, «Фильтры» → `Sheet`, чипы активных фильтров с ×,
   «Сбросить все», «Экспорт» справа) → `Table` → футер (счётчик «1–8 из 180» + `Pagination`).

## Формы

- Одна колонка, ширина до 576px (`max-w-xl`). Короткие связанные поля — в 2 колонки.
- Подпись над полем. Обязательность — не звёздочкой, а пометкой «необязательно» у редких необязательных.
- Кнопки внизу справа: «Отмена» (outline) слева, основная справа.
- Успех — `toast.success` с номером созданной записи.

## Статусы и цвет

- Статус сущности → `StatusBadge`.
- Изменение показателя → `Badge` success/destructive со стрелкой; смысл зависит от `higherIsBetter`.
- Состояние оборудования/линии → `StatusBadge` + подпись с длительностью («Остановка 14 мин»).

## Тексты

- Тон — спокойный, деловой, на «вы» без заискивания.
- Ошибка = что случилось + что делать: «Не удалось сохранить. Нет связи с сервером — повторите через минуту».
- Пустое состояние = почему пусто + действие.
- Не пишите «Успешно!», «Ошибка!» без объяснения.

## Адаптивность

| Ширина | Поведение |
|---|---|
| < 640px (телефон) | Одна колонка, таблицы → карточки, BottomNav/ActionBar внизу, Drawer вместо Dialog для выбора |
| 640–1023px (планшет) | Две колонки, меню — выезжающая панель, карточка записи — Sheet |
| ≥ 1024px | Постоянное меню 360px, сетки 3–4 колонки, оглавление страницы справа с 1280px |

Правила (impeccable/adapt): адаптация — это перестройка, а не масштабирование; тип ввода определяем по
`pointer: coarse`, а не по ширине; на тач-экране нет наведения — HoverCard и Tooltip только как дополнение;
компоненты, которые живут в разных контекстах (DataTable), адаптируются по ширине **контейнера**.

## Мобильная версия

Каркас экрана: `MobileHeader` → контент → `BottomNav` (разделы) или `ActionBar` (действие над записью).

- Главное действие — внизу, в зоне большого пальца.
- Список записей — карточки: номер, название, статус, 1–2 метрики.
- Выбор из 2–6 вариантов на терминале — крупные кнопки-плитки (≥ 56px), а не Select.
- Подтверждение и выбор — `Drawer` снизу.
- Вход на терминал — PIN на `Numpad`.
- Фильтры — `ChipScroller` над списком, расширенные — в `Sheet`.

Готовые экраны на витрине: список заявок → карточка → закрытие, сводка смены, фиксация простоя, вход по PIN, события.

## Пользовательские дашборды

Режим «Настроить дашборд»: виджеты перетаскиваются за ручку, ширина — в меню «⋯», библиотека — в `Sheet`.
Раскладка сохраняется (на витрине — localStorage; в продукте — профиль пользователя на сервере), есть «Сбросить».
Перетаскивание всегда дублируется другим способом (меню, смена статуса в карточке).

## Навигация: три уровня

| Уровень | Инструменты | Правило |
|---|---|---|
| Платформа | Боковое меню, `ModuleSwitcher`, `ModuleLink`, `RelatedRecords` | Видно, куда ведёт (плитка и цвет модуля); новая вкладка; контекст в URL |
| Модуль | Разделы под плиткой модуля в меню, `Tabs` | Вкладки — виды данных одного раздела, не дублируют меню |
| Запись | `BackLink`, `Breadcrumb`, `RecordPager`, `Tabs variant="line"` | Возврат с фильтрами, путь по иерархии, листание соседних записей |

## Контроль качества (OK / NOK)

Чек-лист поста ОТК: строка = точка контроля (название, норма, `OkNok`). Сверху — счётчики ОК / НОК / Н/П / не проверено и прогресс.
НОК раскрывает обязательное описание и фото. Итог — `Alert` «годен» или «несоответствий: N». Кнопка завершения недоступна,
пока не проверены все точки и не описаны все НОК. На терминале — `size="lg"`.
