# 06. Как развивать кит

## Добавить компонент shadcn

```bash
NODE_USE_ENV_PROXY=1 npx shadcn@latest add <компонент>   # прокси в корпоративной сети
```

Чек-лист:
1. Прочитать добавленный файл: служебные подписи (`sr-only`, `aria-label`) — перевести на русский.
2. Проверить, что нет «сырых» цветов (`bg-blue-500`) — только токены.
3. Добавить раздел в `docs/03-components.md`: назначение, варианты, состояния, правила.
4. Добавить пример на витрину (`src/showcase/pages/*`) с кодом и `Rules`.
5. `npm run build && npm run lint` — без ошибок.
6. Запись в `CHANGELOG.md`.

## Добавить вариант существующему компоненту

Через `cva` в файле компонента, с комментарием `// MGC: …` — чтобы при обновлении
из upstream (`npx shadcn@latest add button --diff`) было видно наши правки.

## Изменить или добавить токен

1. `src/styles/tokens.css` — в `:root` **и** в `.dark`.
2. `src/index.css` — связка `--color-<имя>: var(--<имя>)` в `@theme inline`.
3. `docs/02-tokens.md` — строка в таблице.
4. Проверить контраст: текст ≥ 4.5:1 на своём фоне в обеих темах.

## Продуктовый компонент (`src/components/mgc`)

Создаём, только если паттерн повторяется в 2+ модулях. Собирается из компонентов `ui/`,
без собственных цветов. Обязательно: спецификация в `03-components.md` и пример на витрине.

## Обновление shadcn-компонентов

```bash
npx shadcn@latest add button --diff     # посмотреть, что изменилось в upstream
```
Файлы с пометками `// MGC:` — сливать вручную, не через `--overwrite`.
